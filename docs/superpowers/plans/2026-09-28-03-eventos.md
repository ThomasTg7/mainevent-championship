# Plan 03 — Eventos, cartelera, resultados y entradas · Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Crear eventos con cartelera por bloques ordenables, registrar resultados con todos los métodos (también en vivo desde el celular), y mostrar eventos, resultados, historial de peleadores y entradas en el sitio.

**Architecture:** Reglas de resultado puras en `src/domain/bout-result.ts` (validación, normalización, formato). Feature `src/features/events` (eventos, bloques, peleas) y `src/features/results`. Las páginas públicas usan caché con tags (`event:<id>`, `fighter:<id>`) invalidados al guardar; durante `en_vivo` la página del evento se refresca cada 20 s.

**Tech Stack:** Heredado. dnd-kit (armador de cartelera), date-fns-tz (`America/Santiago`).

**Spec:** `docs/superpowers/specs/2026-09-28-guerra-campal-design.md` (§3, §4.4, §4.5, §4.6, §6 Noche de pelea)

- Hereda Plan 00–02.

Formularios: `<MediaField kind name media />` / `<MediaGalleryField name media />`, con el `media` inicial cargado por la página. Lecturas: **una** llamada a `getMediaByIds` por página con todos los ids juntos (nunca una por fila). Público: `<MediaImage media sizes priority? />` (`sizes` obligatorio; `priority` solo en la imagen LCP). Lecturas públicas cacheadas: tag de la entidad **y** `mediaCacheTag(id)` de cada imagen. Toda FK a imágenes es `references media(id) on delete restrict`, con índice, y se registra en `src/features/media/references.ts`; las actions validan los ids con `assertUsableMedia`.
- Enumeraciones exactas:
  - `event_status`: `scheduled | live | completed | cancelled` (UI: Programado, En vivo, Finalizado, Cancelado)
  - `bout_status`: `scheduled | completed | cancelled`
  - `bout_level`: `pro | amateur`
  - `outcome`: `red_win | blue_win | draw | no_contest`
  - `method`: `ko_tko | submission | decision | technical_decision | disqualification | no_contest`
  - `ko_tko_type`: `ko | tko_strikes | tko_doctor | tko_corner | tko_injury`
  - `submission_type`: `tap | verbal | strikes`
  - `decision_type`: `unanimous | split | majority`
  - `nc_reason`: `accidental_foul | overturned | other`
  - `bonus`: `fight_of_night | performance_of_night | ko_of_night | sub_of_night`
- Catálogo inicial de sumisiones: Mataleón, Guillotina, Triángulo, Palanca de brazo, Kimura, Americana, D'Arce, Anaconda, Atadura de brazo con el cuello, Estrangulación norte-sur, Llave de talón, Llave de tobillo, Kneebar.
- `scheduled_rounds ∈ {3, 5}`; `round_seconds` por defecto 300, rango 60–600.
- Formato de línea de resultado: `"{Ganador} vence a {Perdedor} · {Método}{ (detalle)} · R{round} {m:ss}"`; empate: `"{Rojo} y {Azul} empatan · Decisión {tipo}"`; NC: `"{Rojo} vs {Azul} · Sin resultado ({motivo})"`.
- Horas en `America/Santiago`; se guardan en UTC (`timestamptz`).
- Página de evento en vivo refleja un resultado guardado en ≤ 30 s.

## Review Focus

- Tiempo "5:00" en un round de 5:00 es válido; "5:01" no; "0:00" no; formatos "342", "3.42", "03:42" → solo `m:ss`/`mm:ss` aceptados con mensaje claro.
- Mover una pelea a otro bloque y reordenar deja `sort_order` contiguo (0..n−1) en ambos bloques.
- Editar un resultado ya guardado (corrección) recalcula récords sin duplicar y queda en auditoría con el diff.
- Cancelar una pelea con resultado debe exigir limpiar el resultado primero.
- La misma persona en esquina roja y azul, o un peleador en dos peleas del mismo evento, se rechaza con mensaje.

### Task 1: Reglas de resultado (dominio puro)

**Files:**
- Create: `src/domain/bout-result.ts`, `src/domain/bout-result.test.ts`, `src/domain/clock.ts`, `clock.test.ts`

**Interfaces:**
- Produces:
  ```ts
  parseClock(input: string): number | null          // '3:42' → 222; inválido → null
  formatClock(seconds: number): string               // 222 → '3:42'
  type BoutResultInput = {
    outcome; method; koTkoType?; submissionTechniqueId?; submissionType?; decisionType?;
    dqReason?: string; ncReason?; ncNote?: string;
    endRound?: number; endTimeSeconds?: number;
    referee?: string; scorecards?: { judge: string; red: number; blue: number }[];
    bonuses?: Bonus[]; videoUrl?: string; notes?: string;
  };
  type BoutContext = { scheduledRounds: 3|5; roundSeconds: number };
  validateBoutResult(input: BoutResultInput, ctx: BoutContext): { ok: true; value: NormalizedResult } | { ok: false; errors: Record<string, string> }
  suggestDecisionType(scorecards): { outcome: 'red_win'|'blue_win'|'draw'; decisionType: 'unanimous'|'split'|'majority' } | null
  formatResultLine(r: NormalizedResult & { redName: string; blueName: string; techniqueName?: string }): string
  ```
  Normalización: `decision`/`technical_decision` con round vacío → `endRound = scheduledRounds`, `endTimeSeconds = roundSeconds` solo para `decision`.

- [ ] **Step 1: Tests que fallan:**
  - `parseClock('3:42') === 222`, `parseClock('03:42') === 222`, `parseClock('342') === null`, `parseClock('3:60') === null`
  - `red_win` + `no_contest` → error en `method`; `draw` + `ko_tko` → error; `no_contest` + `decision` → error
  - `ko_tko` sin `koTkoType` → error `koTkoType: 'Elige el tipo de KO/TKO'`
  - `submission` sin técnica → error; `endRound: 4` con 3 rounds → error `'El round no puede ser mayor a 3'`; `endTimeSeconds: 301` con 300 → error `'El tiempo no puede superar 5:00'`
  - `decision` sin round → normaliza a `endRound 3, endTimeSeconds 300`
  - `suggestDecisionType([{red:29,blue:28},{red:29,blue:28},{red:28,blue:29}])` → `{ outcome:'red_win', decisionType:'split' }`; `[29-28, 28-28, 29-28]` → `majority` rojo; `[29-28, 28-29, 28-28]` → `{ outcome:'draw', decisionType:'split' }`
